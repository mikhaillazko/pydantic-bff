# Migrating from 0.3 to 0.4

Version 0.4 makes the raw side of the resolve pipeline typed. Existing
`list[dict]` handlers continue to run, but `TypedDict` is now the recommended
contract and is checked against the resolved output model at `finalize()`.

## Raw rows

```python
class TeamRaw(TypedDict):
    id: int
    owner_id: int | None


class TeamDTO(BaseModel):
    id: int
    owner: Annotated[
        UserDTO | None,
        Resolve(FetchUsers, source='owner_id'),
    ]


@app.queries(FetchTeams)
def fetch_teams(...) -> list[TeamRaw]:
    ...
```

fastbff checks ordinary raw fields against their DTO fields and derives the raw
key type of a resolve field from `EntityQuery[K, V]`. A declaration mismatch is
a `QueryRegistrationError` at finalize/mount time. `dict` and `Mapping` remain
available when the shape is intentionally dynamic, but receive no field checks.

## SQLAlchemy converter

Pass the raw row type, not the resolved DTO container:

```python
# 0.3
converter.execute_all(statement, list[TeamDTO])

# 0.4
converter.execute_all(statement, TeamRaw)
```

Mapping rows are validated against `TeamRaw` by default, so missing or
mislabelled columns fail at the database boundary. Use `validate=False` only on
a trusted hot path.
